# Как участвовать в разработке

Правила для людей и ИИ-агентов (для агентов — также [`AGENTS.md`](AGENTS.md)).

## Коммиты и PR

* Коммиты — конвенциональные: `fix` / `feat` / `refactor` / `docs` / `chore`,
  описание на русском, один коммит = одна логическая единица.
* В конце описания — ссылка на issue: `Closes #N` (issue закроется при мерже).
* Ветка: `issue-NN-краткое-имя` (например, `issue-12-cost-rounding`).
* PR = один лейбл типа (`bug`/`enhancement`/`docs`/`refactor`/`perf`) +
  1-2 лейбла зоны + размер.

### Definition of Done (чеклист PR)

- [ ] `make test-api` — зелёное (новые поведения покрыты тестами);
- [ ] `cd web && npm run build` — без ошибок;
- [ ] минимальный diff: не трогать несвязанное, без переформатирования;
- [ ] UI-изменения — скриншот в PR;
- [ ] заполнен [шаблон PR](.github/PULL_REQUEST_TEMPLATE.md);
- [ ] все пункты «Приёмки» из issue выполнены (агент — по чеклисту в issue).

## Лейблы

| Группа | Лейблы | Смысл |
|---|---|---|
| тип | `bug` `enhancement` `docs` `refactor` `perf` | что это |
| зона | `api` `web` `cost` `model-tab` `gpu` `system` `logs` `alerts` `deploy` | где правим (1-2) |
| размер | `size:S` `size:M` `size:L` | <1 ч / <1 день / >1 дня |
| приоритет | `P0` `P1` `P2` `P3` | down / важно / план / косметика |
| агент | `agent:ready` `agent:in-progress` `agent:needs-review` | статус задачи для ИИ-агента |
| прочее | `good-first-issue` | простая стартовая задача |

Создание лейблов на GitHub: `./scripts/setup-labels.sh` (нужен `gh` + авторизация).

## Правила трекера

1. **Issue без чеклиста «Приёмки» не получает `agent:ready`** — сначала
   дописать критерии (что считать готовым + команды проверки).
2. Один issue = одна задача. Большое изменение — разбить (связь `Related #N`).
3. Закрыл issue кодом — `Closes #N` в коммите/PR; обсуждение, которое не
   привело к задаче — закрывать с комментарием.

## Пайплайн «человек + ИИ-агент»

```
человек: issue (шаблон bug/feature/task-agent) + чеклист приёмки
   → лейблы: тип/зона/размер + agent:ready
агент:   берёт задачу (agent:in-progress), работает строго по чеклисту
   → PR (чеклист DoD), лейбл agent:needs-review
человек: ревью, мерж → issue закрывается по Closes #N
```

Задачи для агентов создавать шаблоном [`.github/ISSUE_TEMPLATE/task-agent.md`](.github/ISSUE_TEMPLATE/task-agent.md) —
он машинно-читаемый: `Контекст` (файлы), `В скоупе / Не трогать`,
`Приёмка` (чеклист), `Проверка` (команды). Агент не додумывает вне этих секций;
человек, читая такой issue, получает готовое ТЗ.
